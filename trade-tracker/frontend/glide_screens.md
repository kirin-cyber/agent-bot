## Glide画面設計（4画面構成）

---

### 画面1: アップロード画面

**概要**: スクショを選択してMake Webhookへ送信する起点画面

#### タブ切り替え

| タブ | 用途 | 遷移先Webhook |
|------|------|----------------|
| エントリー | 新規エントリーの記録 | `trade_entry_webhook` |
| 決済 | 既存ポジションの決済 | `trade_close_webhook` |

#### エントリータブ

1. 画像選択ボタン（PNG/JPEG）
2. 「送信」ボタン → Make Webhook（entry）へPOST
3. レスポンス受信後 → 画面2（確認・修正画面）へ遷移

#### 決済タブ

1. 未決済リスト（画面4）から対象を選択
2. 画像選択ボタン（PNG/JPEG）
3. 「送信」ボタン → Make Webhook（close）へPOST
4. レスポンス受信後 → 画面3（完了画面）へ遷移

#### 送信データ形式

```json
{
  "image": "Base64文字列",
  "tab": "entry" or "close",
  "management_id": 123
}
```

- `tab`: エントリータブ → `"entry"`、決済タブ → `"close"`
- `management_id`: 決済タブでのみ送信（未決済リストから選択した管理ID）

---

### 画面2: 確認・修正画面

**概要**: Makeから返却されたAI読み取り結果をユーザーが確認・修正する

#### データソース

- Make Webhookレスポンスの `parsed_data`

#### 表示項目（修正可能なフォーム形式）

| フィールド | 対応JSON | 入力タイプ | 備考 |
|-----------|----------|-----------|------|
| 日付 | `date` | テキスト | MM/DD形式 |
| 時刻 | `time` | テキスト | HH:MM形式 |
| 講師名 | `instructor` | ドロップダウン | よっとん/うなぎ/カエデ/処刑ちゃん/小鳥/sixamo/ミカサ |
| 銘柄 | `symbol` | テキスト | USD/JPY, XAU/USD, NAS100 等 |
| 方向 | `direction` | ドロップダウン | Buy / Sell |
| エントリー価格 | `entry_price` | 数値 | |
| SL | `stop_loss` | 数値 | 損切り価格 |
| TP | `take_profit` | 数値 | 利確価格 |
| メッセージ原文 | `message` | テキストエリア | 読み取り元の原文 |

#### アクション

| ボタン | 動作 |
|--------|------|
| 「登録する」 | 確認済みデータでGoogle Sheetsへの書き込みをトリガー → 画面3へ遷移 |
| 「キャンセル」 | 画面1（アップロード画面）へ戻る |

---

### 画面3: 完了画面

**概要**: 記録完了を通知し、発行された管理IDを表示する

#### 表示内容

| 要素 | 内容 | スタイル |
|------|------|----------|
| メッセージ | 「記録完了」 | 大きめのテキスト |
| 管理ID | `{{management_id}}` | **大きく目立つ表示**（ユーザーが控えやすいように） |

#### アクション

| ボタン | 動作 |
|--------|------|
| 「トップへ戻る」 | 画面1（アップロード画面）へ遷移 |

---

### 画面4: 未決済リスト画面

**概要**: 現在未決済のポジション一覧を表示し、決済対象を選択する

#### データソース

- Google Sheets `トレード記録` シート
- フィルタ条件: D列（勝敗） = `"Wait"`

#### 表示項目

| 表示 | 対応列 | 説明 |
|------|--------|------|
| 管理ID | A列 | タップ時に決済フローへ引き継ぎ |
| 日付 | B列 | MM/DD |
| 講師名 | C列 | |
| 通貨 | E列 | 銘柄 |
| 方向 | F列 | Buy / Sell |
| エントリー価格 | G列 | |

#### アクション

- リスト項目をタップ → 画面1の決済タブへ遷移
- 選択した管理ID（A列の値）を自動的に引き継ぎ
- ユーザーは画像を選択して送信するだけで決済フローが開始

---

### 画面遷移図

```
画面1（アップロード）
├── エントリータブ
│   └── 送信 → Make(entry) → 画面2（確認・修正）
│                                └── 登録する → Sheets書き込み → 画面3（完了）
│                                └── キャンセル → 画面1
└── 決済タブ
    ├── 未決済リスト表示 → 画面4（未決済リスト）
    │                       └── タップ → 画面1（決済タブ、管理ID付き）
    └── 送信 → Make(close) → 画面3（完了）
```
